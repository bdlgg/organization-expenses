# Система учёта расходов организации

Учебный проект для учёта расходов организации. Консольная версия предыдущих
практических работ сохранена; веб-приложение построено на Django 5.2 и Django ORM.

## Возможности веб-приложения

- просмотр реестра расходов и карточки отдельной операции;
- фильтрация через `ExpenseFilterForm` на основе `forms.Form` (сумма, категория,
  подразделение, поиск по реквизитам и документ);
- сортировка и пагинация с сохранением GET-параметров;
- создание и редактирование расходов через `ExpenseForm` (`ModelForm`);
- серверная валидация суммы, связанных справочников и загружаемого изображения;
- изменение статуса расхода отдельным POST-запросом с CSRF-защитой;
- загрузка скана/фотографии подтверждающего документа;
- общая статистика, агрегаты по категориям и подразделениям;
- справочники категорий, подразделений и подтверждающих документов;
- обработка отсутствующих карточек с ответом 404.

## Структура предметной области

- `Expense` — сумма, категория, подразделение, подтверждающий документ, комментарий,
  статус, адрес карточки и необязательное изображение документа.
- `Category` — справочник категорий расходов.
- `Department` — подразделения организации.
- `Document` — подтверждающие документы.

Связи `Expense` со справочниками используют `ForeignKey` с `on_delete=PROTECT`,
поэтому категория, подразделение или документ не могут быть удалены, пока на них
ссылаются расходы. Все web-представления используют Django ORM. Исходная база
`data/organization_expenses.sqlite` и консольные JSON-данные сохранены для предыдущих
практических работ и переноса данных.

## Основные маршруты

| Адрес | Назначение |
| --- | --- |
| `/` | Главная страница и сводные показатели |
| `/expenses/` | Реестр расходов, фильтрация, сортировка и пагинация |
| `/expenses/new/` | Создание расхода |
| `/expenses/<slug>/` | Карточка расхода и управление статусом |
| `/expenses/<slug>/edit/` | Редактирование расхода |
| `/expenses/statistics/` | Статистика расходов и фильтр по порогу |
| `/categories/` | Справочник категорий с агрегатами |
| `/departments/` | Справочник подразделений с агрегатами |
| `/documents/` | Справочник документов с агрегатами |
| `/admin/` | Административная панель Django |

Старые числовые адреса карточек `/expenses/<id>/` перенаправляются на адрес со
`slug`, чтобы сохранить прежние ссылки.

## Формы Django (ПР11)

`expenses/forms.py` содержит обычные формы для GET-фильтрации и порога статистики,
а также `ExpenseForm` на основе `ModelForm`. В `ExpenseForm.Meta.fields` явно
перечислены только поля, которые разрешено менять пользователю. Поля `status` и
`slug` назначаются приложением и в эту форму не входят. При редактировании в форму
передаётся существующий объект через `instance`.

Формы используют Bootstrap-виджеты, подписи и подсказки. Ошибки полей и общие
ошибки отображаются в шаблонах. Для загрузки изображения используется `ImageField`,
`request.FILES` и `enctype="multipart/form-data"`. Изображения сохраняются в
`media/receipts/`, а в базе хранится путь к файлу. Размер ограничен 5 МБ; Django/Pillow
проверяет, что загружен корректный файл изображения.

## Запуск на macOS / Linux

Из корневого каталога проекта:

```bash
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
pytest -v
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`. Виртуальное окружение и `.git` входят в
передаваемый архив и сохраняют исходную историю. Если окружение перенесено на другой
компьютер и путь к Python в нём недействителен, создайте новое окружение и установите
зависимости из `requirements.txt`; исходный каталог `.venv` в данном архиве не удалён.

Для разработки включён `DEBUG = True`, чтобы локальный сервер Django мог обслуживать
медиафайлы. Перед развёртыванием в рабочей среде необходимо отключить DEBUG и
настроить раздачу `MEDIA_ROOT` на уровне веб-сервера или файлового хранилища.

## Проверки ПР11

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
pytest -v
```

При проверке форм необходимо пройти сценарии: фильтрация корректными и ошибочными
GET-параметрами; создание расхода; отклонение некорректной суммы; редактирование
существующей записи; ошибка 404 для отсутствующего расхода; изменение статуса только
через POST; загрузка изображения и отображение альтернативного сообщения, когда
изображение не приложено.

## Консольная версия

Предыдущая консольная программа и её JSON-хранилище сохранены отдельно:

```bash
python main.py
```
