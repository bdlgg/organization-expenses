# Система учёта расходов организации

Учебный проект для учёта расходов организации. В проекте сохранены консольная
версия и объектная модель предыдущих практических работ, а веб-приложение Django
переведено с ручных SQL-запросов на Django ORM в рамках ПР9.

## Функциональность

- главная страница со сводными показателями расходов;
- список расходов с поиском по категории, подразделению и документу;
- фильтрация по минимальной сумме, категории и подразделению;
- сортировка расходов по сумме, категории и подразделению;
- постраничный вывод списка расходов с сохранением параметров фильтрации;
- карточка отдельного расхода со связанными справочниками;
- статистика: количество, сумма, среднее, минимум и максимум;
- группировка расходов по категориям и подразделениям;
- отбор групп по пороговой сумме через агрегаты ORM;
- страницы категорий, подразделений и документов;
- административная панель Django для справочников и расходов;
- исходная консольная программа `main.py` и JSON-хранилище предыдущих этапов.

## Модели и связи

Структура данных соответствует предметной области учёта расходов:

| Модель | Поля | Связи |
| --- | --- | --- |
| `Category` | `id`, `name` | Одна категория связана со многими расходами |
| `Department` | `id`, `name` | Одно подразделение связано со многими расходами |
| `Document` | `id`, `number` | Один документ может подтверждать несколько расходов |
| `Expense` | `id`, `amount`, `category`, `department`, `document` | Три внешних ключа на справочники |

Связи описаны полями `ForeignKey` с `on_delete=models.PROTECT` и
`related_name="expenses"`. Удалить категорию, подразделение или документ,
который используется расходом, нельзя: это защищает историю учёта от потери
связанных записей. Сумма хранится в `DecimalField`, ограничена снизу нулём
валидатором и ограничением базы данных.

## Архитектура доступа к данным после ПР9

Представления (`views.py`) обращаются к моделям через Django ORM. Используются
`filter()`, `exclude()`, `get_object_or_404()`, `select_related()`, `order_by()`,
`annotate()`, `aggregate()`, `Count()`, `Sum()`, `Avg()`, `Min()`, `Max()` и
`Paginator`. В проекте реализованы разные ORM-выражения для получения списков и
карточек, четырёх видов фильтрации, двух вариантов поиска, сортировки, работы со
связями, агрегирования и постраничного вывода. Прямые вызовы `sqlite3` и ручные
SQL-запросы из веб-представлений удалены.

`sql/schema.sql`, `sql/queries.sql`, `db/database.py`, `db/queries.py` и исходная
база `data/organization_expenses.sqlite` сохранены как материалы предыдущего
этапа ПР7 и источник миграции данных. Веб-представления их не используют.

## Перенос данных из ПР7

В проекте используются две SQLite-базы с разными назначениями:

- `data/organization_expenses.sqlite` — исходная база ПР7, остаётся без изменений;
- `db.sqlite3` — целевая база, управляемая Django ORM.

После применения миграций данные переносятся скриптом
`db/import_sqlite_to_orm.py`. Он сохраняет исходные идентификаторы, переносит
справочники до расходов, проверяет внешние ключи и выполняет запись в одной
транзакции. Повторный запуск обновляет записи по первичному ключу, не создавая
дубликаты.

## Запуск на macOS / Linux

Из корневой папки проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python manage.py migrate
python db/inspect_source_db.py
python db/import_sqlite_to_orm.py
python manage.py check
python manage.py showmigrations
pytest -v
flake8 . --extend-exclude=venv
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/`.

## Административная панель

Создайте администратора и запустите сервер:

```bash
python manage.py createsuperuser
python manage.py runserver
```

Панель доступна по адресу `http://127.0.0.1:8000/admin/`. В ней зарегистрированы
категории, подразделения, документы и расходы.

## Консольная версия

Предыдущая консольная версия запускается отдельно и по-прежнему использует
JSON-файлы:

```bash
python main.py
```

## Текущее состояние

В ПР9 описаны Django ORM-модели четырёх сущностей, связи между расходами и
справочниками, миграции и скрипт переноса данных из исходной базы ПР7. Страницы
сохранены и переведены на ORM; список расходов поддерживает фильтрацию,
сортировку и пагинацию. Административная панель позволяет просматривать и
управлять записями. Локальная база `db.sqlite3` создаётся миграциями и не входит
в Git; исходная `data/organization_expenses.sqlite` сохраняется для повторного
переноса.
