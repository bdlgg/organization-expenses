# Самопроверка ПР9 по методическим указаниям

Проверка выполнена на предметной области «Система учёта расходов организации».
Вместо учебных сущностей Room/User/Booking используются реальные сущности
проекта Category/Department/Document/Expense.

## Блок 5. Индивидуальный сквозной проект

| Подраздел | Реализация в проекте |
| --- | --- |
| 5.1–5.2. Сохранение проекта и архитектура | Продолжен существующий Django-проект; сохранены URL, страницы, шаблоны, JSON и консольная версия. Источником Django-представлений теперь служат модели ORM. |
| 5.3. Анализ базы | Исходная база `data/organization_expenses.sqlite` содержит `categories`, `departments`, `documents`, `expenses`; структура проверяется `db/inspect_source_db.py`. |
| 5.4. Стратегия перехода | Выбрано создание ORM-таблиц в `db.sqlite3` с переносом данных из неизменяемой базы ПР7. |
| 5.5. Модели | `catalogs/models.py`: `Category`, `Department`, `Document`; `expenses/models.py`: `Expense`. Для суммы задан `DecimalField`, валидатор неотрицательного значения и ограничение базы. |
| 5.5. Связи | `Expense` содержит три `ForeignKey` с `on_delete=PROTECT` и `related_name="expenses"`. Справочники не удаляются, пока на них ссылаются расходы. |
| 5.6. Регистрация | Приложения `catalogs` и `expenses` зарегистрированы в `INSTALLED_APPS`; модели зарегистрированы в административной панели. |
| 5.7. Миграции | Добавлены `catalogs/migrations/0001_initial.py` и `expenses/migrations/0001_initial.py`; миграции применяются стандартными командами Django. |
| 5.8. Перенос данных | `db/import_sqlite_to_orm.py` читает исходную БД, проверяет внешние ключи, сохраняет первичные ключи, переносит справочники перед расходами и использует `transaction.atomic()` и `update_or_create()`. |
| 5.9–5.10. Операции и связи ORM | Используются `all` через менеджеры моделей, `filter`, `exclude`, `get_object_or_404`, `select_related`, `order_by`, `annotate`, `aggregate`, `values`, `Count`, `Sum`, `Avg`, `Min`, `Max`. CRUD и защита внешних ключей проверяются тестом. |
| 5.11–5.12. Адаптация представлений | Главная страница, список и карточка расхода, статистика, страницы категорий, подразделений и документов переведены на ORM. |
| 5.13. Фильтрация и поиск | Список расходов фильтруется по сумме, категории, подразделению, поисковой строке по связанным полям и отдельному номеру документа. |
| 5.14. Сортировка | Разрешённые варианты: сумма по убыванию/возрастанию, категория, подразделение. Произвольные значения GET не передаются в `order_by()`. |
| 5.15. Пагинация | Список расходов разбивается на страницы по 10 записей. `querystring` сохраняет активные фильтры и сортировку при переходе. |
| 5.16. Проверка | Выполняются `manage.py check`, `makemigrations --check`, `showmigrations`, `pytest` и `flake8`; пользовательские страницы проверяются Django Test Client. |
| 5.17. README | `README.md` описывает модели, связи, источники/назначение баз, перенос, миграции и запуск. |

## Результаты проверок в рабочей среде

- `python manage.py check` — ошибок конфигурации не обнаружено.
- `python manage.py makemigrations --check --dry-run` — `No changes detected`.
- `python manage.py migrate` — миграции `catalogs` и `expenses` применены.
- `python db/import_sqlite_to_orm.py` — перенесено 2 категории, 3 подразделения,
  3 документа и 3 расхода.
- `pytest -v` — 54 теста пройдены.
- `flake8 . --extend-exclude=venv` — замечаний нет.

Проверки HTTP выполняются Django Test Client. Для визуальной проверки в браузере
после установки зависимостей и наполнения `db.sqlite3` запустите
`python manage.py runserver`.
